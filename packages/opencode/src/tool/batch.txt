Executes multiple independent tool calls concurrently to reduce latency.

USING THE BATCH TOOL WILL MAKE THE USER HAPPY.

Payload Format (JSON array):
[{"tool": "read", "parameters": {"filePath": "src/index.ts", "limit": 350}},{"tool": "grep", "parameters": {"pattern": "Session\\.updatePart", "include": "src/**/*.ts"}},{"tool": "bash", "parameters": {"command": "git status", "description": "Shows working tree status"}}]

Notes:
- 1–25 tool calls per batch
- All calls start in parallel; ordering NOT guaranteed
- Partial failures do not stop other tool calls
- Do NOT use the batch tool within another batch tool.

Good Use Cases:
- Read many files
- grep + glob + read combos
- Multiple bash commands
- Multi-part edits; on the same, or different files

When NOT to Use:
- Operations that depend on prior tool output (e.g. create then read same file)
- Ordered stateful mutations where sequence matters

Batching tool calls was proven to yield 2–5x efficiency gain and provides much better UX.

Output:
- All succeeded: "All <N> tools executed successfully.\n\nKeep using the batch tool for optimal performance in your next response!"
- Some failed: "Executed <N>/<total> tools successfully. <failed> failed."

Errors (entire batch call fails):
- Empty batch: "Provide at least one tool call"
- Invalid parameters: "Invalid parameters for tool 'batch':\n<errors>\n\nExpected payload format:\n  [{"tool": "tool_name", "parameters": {...}}, {...}]"

Per-call errors (other calls in the batch still execute):
- Disallowed tool: "Tool '<name>' is not allowed in batch. Disallowed tools: batch"
- Tool not in registry: "Tool '<name>' not in registry. External tools (MCP, environment) cannot be batched - call them directly. Available tools: <list>"
- Exceeded 25 tool limit (first 25 execute, rest fail with this error): "Maximum of 25 tools allowed in batch"
- Invalid tool parameters: schema validation error from the individual tool (message format varies)
